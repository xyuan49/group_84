
# GlucoTrack

GlucoTrack is a diabetes management dashboard developed by Group 84 for Georgia Tech's CS 6440: Introduction to Health Informatics.

The application uses a FastAPI backend, a SQLite database, and a React frontend built with Vite.

## Features

- Select patients and view their diabetes-related health information.
- Visualize glucose readings, HbA1c history, and insulin usage.
- Manually log glucose readings, insulin doses, and meals.
- Display rule-based glucose alerts.
- Run automated frontend and end-to-end tests.

## Demonstration Data

GlucoTrack uses synthetic patient records generated by Synthea, alongside glucose, insulin, and meal data from the UCI Diabetes and Shanghai T2DM CGM research datasets.

Research dataset records are paired with synthetic patients for demonstration purposes. They are not actual medical observations of those patients.

**GlucoTrack is an educational project, not a clinical application or a source of medical advice.**

## Prerequisites

Before setting up GlucoTrack, install the following:

- **Git** — to clone the project repository.
- **Python 3.10 or newer** — to run the FastAPI backend and database loaders.
- **Node.js 24** — to run the React/Vite frontend.
- **npm** — included with Node.js.

You will also need an internet connection to install the project dependencies and obtain the required research datasets.

The instructions below use macOS/Linux terminal commands. Windows users may need to adjust the virtual environment activation commands.

## Getting Started

### 1. Clone the Repository

Open a terminal and run:

```bash
git clone https://github.com/xyuan49/group_84.git
cd group_84
```

All subsequent setup instructions assume you are starting from the `group_84` project directory.

### 2. Set Up the Backend

Open a terminal in the project root and run:

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

This creates a Python virtual environment and installs the dependencies required by the FastAPI backend.

Keep this terminal open for the database setup and backend startup steps.

### 3. Prepare the Demo Datasets

GlucoTrack uses three datasets to populate its demonstration database:

1. **Synthea:** Synthetic patient demographics, conditions, medications, and clinical observations in FHIR format.
2. **UCI Diabetes:** Glucose readings, insulin administration, and meal records.
3. **Shanghai T2DM CGM:** Continuous glucose monitoring and dietary records.

Before building the database, download and prepare the datasets following the instructions in [data/README.md](data/README.md).

Make sure the downloaded files are stored in the locations expected by the backend data-loading scripts.

**Important:** UCI and Shanghai records are paired with synthetic Synthea patients for demonstration. These records do not represent actual clinical histories of the synthetic patients.

### 4. Build the Demo Database

After preparing the datasets, run the following commands from the `backend/` directory with your Python virtual environment activated:

```bash
python -m app.loaders.synthea ../data/synthea_t2d
python -m app.loaders.uci ../data/uci_raw/Diabetes-Data
python -m app.loaders.shanghai ../data/shanghai_raw/Shanghai_T2DM
```

Run these loaders in the order shown:

1. **Synthea:** Creates the SQLite database and loads 85 synthetic patients with their FHIR records.
2. **UCI:** Adds glucose, insulin, and meal data for 27 insulin-treated patients.
3. **Shanghai:** Adds CGM readings and dietary records for 41 patients who are not receiving insulin.

The resulting SQLite database is stored at `backend/glucotrack.db`.

After all three loaders complete, 68 of the 85 patients have detailed glucose histories. The remaining 17 patients have synthetic clinical data without UCI or Shanghai glucose series.

The database file is excluded from Git, so each developer must generate it locally.

For additional loader details, see [backend/README.md](backend/README.md).

### 5. Start the Backend Server

From the `backend/` directory, with your Python virtual environment activated, run:

```bash
uvicorn app.main:app --reload
```

The FastAPI server should start at:

- **Backend API:** http://localhost:8000
- **Interactive API documentation:** http://localhost:8000/docs
- **Health check:** http://localhost:8000/api/health

Keep this terminal running while using the GlucoTrack dashboard.

If port 8000 is already occupied, stop the existing process before starting another backend server.

### 6. Set Up and Start the Frontend

Open a **new terminal window** and navigate to the project's frontend directory:

```bash
cd frontend
```

If you are using Node Version Manager (nvm), select Node.js 24:

```bash
nvm use 24
```

Install the frontend dependencies:

```bash
npm ci
```

Start the Vite development server:

```bash
npm run dev
```

Open the dashboard in your browser:

**http://localhost:5173**

Keep both the frontend and backend servers running while using GlucoTrack.

The frontend connects to the backend at `http://localhost:8000` by default. To use a different API address, set the `VITE_API_URL` environment variable before starting Vite.

## Running Automated Tests

GlucoTrack includes frontend unit tests and a Playwright end-to-end test.

### Frontend Unit Tests

From the `frontend/` directory, run:

```bash
npm test
```

This runs the frontend test suite using Vitest.

### Playwright End-to-End Test

The Playwright test checks the following workflow:

1. Open the GlucoTrack dashboard.
2. Select a patient.
3. Enter and save a glucose reading.
4. Verify that the backend accepts the reading.
5. Verify that the glucose chart's displayed reading count updates.

Before running the test, ensure that:
- The demo database has been built.
- The FastAPI backend is running at `http://localhost:8000`.
- The Vite frontend is running at `http://localhost:5173`.

From the `frontend/` directory, install the Playwright Chromium browser:

```bash
npx playwright install chromium
```

Run the end-to-end test:

```bash
npx playwright test tests/e2e/glucose-logging.spec.js --project=chromium
```

A successful run should report `1 passed`.

**Note:** This test writes a demonstration glucose reading to the local SQLite database. Repeated executions can add additional test readings.

### Frontend Production Build

To verify that the React frontend builds successfully, run:

```bash
npm run build
```
